## Completed-session read contract (v1)

Grace is the source of truth for completed sessions. Focus may request only
local, read-only access after explicit opt-in. Grace authenticates the calling
application and checks a separate, revocable history grant on every read,
including continuation requests. Launch consent, a launch ACK and live timer
state confer no history access. Missing Grace, refused or revoked access and
failed reads are unavailable; hide previously fetched rows while unavailable.
This packet defines behavior, not a transport, permission prompt or runtime
integration. No history, cursor or credential leaves the device.

A successful page has `version: 1`, a non-negative safe integer `revision`,
an explicit Boolean `cleared`, a `records` array and `nextCursor` (opaque
nonempty string or `null` at the end). A record has an opaque, nonempty
string `id` and safe integer UTC Unix millisecond `startMs` and `endMs`
with `endMs > startMs`. Use actual elapsed time, not the requested duration
or the launch time. Grace emits only completed sessions, assigns each ID
once, and never reuses a deleted ID. Focus skips malformed records before
deduplicating, compares IDs exactly, and keeps the first valid occurrence
within a snapshot. Grace keeps intervals stable within that snapshot.

Fetch newest first, with an opaque tie-break chosen by Grace. A root read
establishes a snapshot; continuations append to it only if their revision
matches. Grace issues cursors scoped to the authenticated grant and snapshot.
Focus consumes each cursor once, ignores results from superseded requests,
and restarts at the root if a continuation is invalidated; it must not
combine rows from different snapshots. A new root read replaces the previous
rows, never merges them.

Every history mutation advances the revision. Grace invalidates all older
cursors on deletion or clear; a new root read must omit deleted rows. Focus
drops its old rows and cursors on learning of a newer revision, ignores
older replies, and never restores data from an older snapshot on retry.
Grace marks an empty snapshot caused by an explicit clear as `cleared: true`
until history changes again. Such a snapshot is terminal and has no rows.
An ordinary successful read with no valid records is empty only after the
last page; neither an unfinished empty page nor a failed read proves absence.
An unsupported numeric version is incompatible; a malformed v1 envelope
is unavailable. Neither state displays old rows. A launch ACK is outside
this read protocol and leaves history unchanged.

The [synthetic fixture](fixtures/grace-history.json) and
[`verify-grace-history.cjs`](fixtures/verify-grace-history.cjs) model consumer
outcomes only. They do not test native rendering, identity verification,
authorization enforcement or an actual Grace producer.

### D1 expected state matrix

| Case | Expected outcome |
| --- | --- |
| Populated | Render valid completed sessions with their actual intervals and stable opaque IDs. |
| Valid empty | Show empty history after a successful read with no records. |
| Cleared | Show cleared history; deleted records do not reappear on subsequent pages or reads. |
| Unavailable | Report unavailable, not empty, when history cannot be read. |
| Incompatible | Report incompatible version without treating the response as valid history. |
| Invalid record | Do not display or count the invalid record as a completed session. |
| Duplicate across pages | Count the stable session ID once. |
| Launch ACK only | Do not create a history row. |
