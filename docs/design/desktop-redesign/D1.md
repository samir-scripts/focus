## Scope and acceptance

Specify Grace-owned versioned completed sessions: opaque stable IDs, actual intervals, authentication and paging/dedup/deletion requirements. Separate populated, valid empty, cleared, unavailable and incompatible. Launch ACK is not history.

- [ ] Review every synthetic state and invalid/duplicate records against expected outcomes. No app edits, authorization, Grace writes, real sessions or data access.
- [ ] Use `docs/design/desktop-redesign/fixtures/grace-history.json`. Record expected versus observed outcomes for every row in the D1 matrix.
- [ ] Record reviewed base, commit/tree, OS/browser, command output, screenshots or GIF and hashes. Stop for explicit publication approval; scope and procedure in [packet 00](README.md).

### D1 expected state matrix

| Case | Expected outcome |
| --- | --- |
| Populated | Render valid completed sessions with their actual intervals and stable opaque IDs. |
| Valid empty | Show empty history after a successful read with no records. |
| Cleared | Show cleared history; deleted records do not reappear on subsequent pages or reads. |
| Unavailable | Report unavailable, not empty, when history cannot be read. |
| Incompatible | Report incompatible version without treating the response as valid history. |
| Invalid record | Do not display or count the invalid record as a completed session. |
| Duplicate across pages | Count the stable session ID once. |
| Launch ACK only | Do not create a history row. |
