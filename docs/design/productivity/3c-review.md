## Reproduce with disposable data

1. Build the candidate and the base in separate worktrees with `npm ci` and `npm run build --workspace @focus/desktop`. Do not launch the default app identity or point the app at existing data.
2. Serve one `apps/desktop/dist` on loopback port 1420 (e.g. `python3 -m http.server 1420 --bind 127.0.0.1 --directory apps/desktop/dist`). Start the native shell with a fresh absolute `FOCUS_DATA_DIR` and `npm run tauri -- dev --no-watch --config '{"identifier":"com.focus-local.productivity-3c-review","productName":"Focus 3C Review","build":{"beforeDevCommand":""}}'`. For a separate macOS WebKit profile, place the resulting debug executable in a scratch `.app` with that `CFBundleIdentifier`, ad-hoc sign it and launch it with `open --env FOCUS_DATA_DIR=…`. The evidence directory includes the scratch `Info.plist` and capture helpers. Use no existing profile and do not click browser enrollment.
3. Select Light / Cobalt, then Dark / Cobalt. Keep YouTube selected; capture only the native 960×640 window at 100% for at least 7.2s. Repeat with the other worktree's build served on port 1420, relaunching between builds. Repeat screenshots for all six combinations and views. At 635px use Tab/Space on Add site; test focus after Cancel. At 200% check the same path and click Sites beside the native drag area. To exercise unqualified entry radios only, relaunch the **debug** bundle with a second fresh `FOCUS_DATA_DIR`, `FOCUS_FIXTURE_ENTRY=1` and `FOCUS_FIXTURE_NO_DESKTOP=1`. Never reuse those settings in an ordinary build.
4. Try OS Reduce Motion only in a disposable guest, comparing idle Sites with the pref off and on. Use Chromium for forced-color emulation. Package both extensions with `npm run package:extensions`; open the manifest's toolbar action in a fresh supported Chromium profile and temporarily install the Firefox ZIP in another fresh profile. Test Setup from the popup without enrolling it.
